# Smiljan Coffee

Website for Smiljan Coffee, a manually brewed coffee shop. Built with Next.js 16
(App Router) and TypeScript, with content available in Indonesian and English.

> **Status:** phase one. All pages are live, but the contact details, address,
> opening hours, menu prices and photos are placeholders. Replace them before
> launch — see [Replacing placeholder content](#replacing-placeholder-content).

## Stack

| Concern            | Choice                                        |
| ------------------ | --------------------------------------------- |
| Framework          | Next.js 16 (App Router, Turbopack)             |
| UI                 | React 19, TypeScript, Tailwind CSS v4          |
| i18n               | next-intl 4 (`/id` and `/en` prefixed routes)  |
| Animation          | motion (framer-motion)                         |
| Forms              | zod validation, hand-off to WhatsApp           |
| Icons              | lucide-react                                   |
| Analytics          | Vercel Analytics                               |
| SEO                | Metadata API, JSON-LD, sitemap, robots         |

## Getting started

Requires Node.js 20 or newer.

```bash
npm install
npm run dev
```

Open <http://localhost:3000>. Requests to `/` are redirected to `/id`.

## Scripts

| Script                    | Purpose                                                      |
| ------------------------- | ------------------------------------------------------------ |
| `npm run dev`             | Development server                                           |
| `npm run build`           | Production build                                             |
| `npm run start`           | Serve the production build                                   |
| `npm run lint`            | ESLint                                                       |
| `npm run typecheck`       | `tsc --noEmit`                                               |
| `npm run typegen`         | Regenerate Next.js route types (run after adding a route)    |
| `npm run check:content`   | Validate message files and detect corrupted characters       |
| `npm run images:placeholder` | Regenerate the placeholder images                         |

`npm run check:content` is worth running after any copy change. It verifies that
every `messages/*.json` file parses, that Indonesian and English have matching
keys, and that no unexpected non-Latin characters slipped into the text.

## Routes

Every route is available in both locales.

| Route            | Contents                                                    |
| ---------------- | ----------------------------------------------------------- |
| `/[locale]`      | Hero, signature menu, story teaser, hours, gallery, visit CTA |
| `/[locale]/menu` | Filterable menu with a detail dialog per item               |
| `/[locale]/cerita` | Brand story, process timeline, values, team                 |
| `/[locale]/lokasi`  | Map, directions, hours, facilities, live open status     |
| `/[locale]/galeri`  | Filterable masonry gallery with a lightbox                |
| `/[locale]/reservasi` | Reservation form sent to WhatsApp                        |
| `/[locale]/kontak`   | Contact channels, message form, FAQ                     |

`/sitemap.xml` and `/robots.txt` are generated by `app/sitemap.ts` and
`app/robots.ts`.

## Content

### Translations

UI copy lives in `messages/id/` and `messages/en/`, one file per route plus
`common.json`, `nav.json` and `footer.json`. The two locales must have identical
key sets — `npm run check:content` fails if they drift.

Longer prose that belongs to the business rather than the interface (menu item
descriptions, story paragraphs, FAQ answers) lives in `data/` as
`LocalizedText`, which keeps content and translation side by side:

```ts
const text: LocalizedText = {
  id: 'Deskripsi dalam bahasa Indonesia.',
  en: 'Description in English.'
};
```

Use `lib/utils.ts` `localize()` to read the right field from a server component,
or `useLocale()` in a client component.

### Forms

The reservation and contact forms do not post to a server. They validate with
zod, then open WhatsApp with the message pre-filled so the visitor confirms and
sends it. Each form includes a hidden `company` field; submissions where it is
filled in are discarded silently.

### Analytics

`@vercel/analytics` is mounted in `app/[locale]/layout.tsx` only when the
build runs on Vercel (`process.env.VERCEL`), so local builds ship no analytics
script at all. Vercel Analytics runs in cookieless mode; the one-time notice in
`components/layout/CookieNotice.tsx` explains that to visitors anyway (PRD 5.9).

### Bundle size

Client bundles deliberately keep two heavy dependencies out of the initial
parse: `motion/react` (scoped to pages that animate via
`components/ui/MotionScope.tsx`) and `zod` (schemas are imported on demand in
the form submit handlers, with pure helpers in `lib/reservation-shared.ts`).
The page transition in `app/[locale]/template.tsx` is CSS-only so first paint
never waits on hydration.

## Replacing placeholder content

Everything below is placeholder data awaiting the real details.

1. **`data/site.ts`** — name, legal name, tagline, phone number, email,
   address, coordinates, opening hours, social URLs and facilities. The phone
   number also drives the WhatsApp buttons, the `tel:` link and the JSON-LD, so
   update `whatsapp` and `whatsappDisplay` together. Number format is
   `62XXXXXXXXX` with no `+`, spaces or dashes.
2. **`data/menu.ts`** — the 28 items, their prices, categories and tasting
   notes.
3. **`data/gallery.ts`** — the 12 gallery photos and their categories.
4. **`public/images/`** — replace the generated SVGs with real photography.
   Keep the same filenames to avoid touching the data files, and export at
   roughly 1600px on the long edge. Run `npm run images:placeholder` only when
   you want to regenerate the placeholders.
5. **`app/robots.ts`** — nothing to change, it reads from `data/site.ts`.

The map on `/lokasi` uses a link to Google Maps with the coordinates from
`data/site.ts`, so no map API key is required.

## Deploying

Deploy to Vercel and it works as-is — no environment variables are needed.

```bash
npm run build   # confirm the production build passes first
```

After the first deploy, submit `https://<your-domain>/sitemap.xml` in Google
Search Console, and replace `site.url` in `data/site.ts` with the real domain so
canonical URLs and structured data are correct.

## Known issues

`npm audit` reports 5 high-severity advisories in the ESLint toolchain
(`fast-glob` via `eslint-config-next`). They are dev-only and do not affect the
production build. Forcing a fix would downgrade Next.js past 16, so they are left
alone deliberately. Revisit when the packages publish patched versions.
